# Plan: Fase 3 — login

**Tanggal:** 2026-11-10
**Status:** Disetujui 2026-11-10. Dikerjakan satu langkah per hari, 11–16 Nov (lihat "Tugas per hari").

## Tujuan

Dashboard hanya bisa dibuka setelah login dengan akun sungguhan, dan halaman admin hanya untuk admin. Halaman publik tetap static dan tidak berubah.

## Keputusan user (brainstorm 2026-11-10)

| Hal | Keputusan |
|-----|-----------|
| Hash password | **scrypt bawaan Node** (`node:crypto`), tanpa paket tambahan. Format hash dicek ketat, jadi nilai yang bukan hash (seperti `!no-login` dari seed) selalu ditolak |
| Sesi | **Cookie httpOnly bertanda tangan**, ditambah cek user di database pada setiap request, sehingga akun yang dinonaktifkan langsung tertolak. Tanpa tabel baru |
| Lama sesi | **7 hari** |
| Akun contoh | **Satu password dev acak di `.env.local`**, tidak lewat chat dan tidak di-commit. Seed memakainya untuk semua akun contoh; E2E membacanya dari sana |

## Rancangan

**Password** (`lib/auth/password.ts`):

- **Format hash:** `scrypt$N$r$p$salt$hash`.
- **Verifikasi:** semua format yang tidak dikenal ditolak sebelum menghitung apa pun. Ini syarat dari review Fase 2: pemeriksa yang mengambil panjang kunci dari nilai tersimpan bisa meloloskan password apa pun.
- **Perbandingan:** `timingSafeEqual` dengan panjang tetap.

**Password dev:**

- **Saat seed:** kalau belum ada, `npm run db:seed` membuat `DEV_PASSWORD` acak di `.env.local` (tidak dicetak), lalu memakai hash-nya untuk semua akun contoh.
- **Mengganti password:** `npm run db:set-password <email>` mengganti password satu akun; password-nya diketik tersembunyi di terminal.

**Sesi** (`lib/auth/session.ts`):

- **Cookie:** `httpOnly`, `secure` di produksi, `sameSite=lax`, berlaku 7 hari, berisi id user dan waktu kedaluwarsa.
- **Tanda tangan:** memakai `SESSION_SECRET` dari `.env.local`, yang dibuat otomatis dan tidak dicetak. Caranya (`jose` atau HMAC bawaan Node) diputuskan dari docs Next pada hari itu.

**`getCurrentUser()`** (server-only):

- **Cara kerja:** membaca cookie, lalu mengecek user di database pada setiap request, tanpa cache.
- **Akun nonaktif:** dianggap tidak login.

**Login dan logout:**

- **Form login:** memakai Server Action. Pesan error sama untuk email dan password yang salah, supaya tidak ketahuan email mana yang terdaftar.
- **Tombol Log out:** menghapus cookie.

**Kunci dashboard:**

- **`proxy.ts`:** mengarahkan ke `/login` kalau tidak ada cookie. Ini hanya redirect cepat; pemeriksaan sebenarnya ada di layout dan halaman dashboard.
- **Halaman admin:** diperiksa role-nya, dengan satu daftar path admin (butir 3 `clean-code`).
- **`getPreviewUser`:** dihapus.

**Dashboard tidak lagi static:**

- Halaman dashboard dirender saat request, mengikuti `node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md`.
- Dengan begitu, email di `/dashboard/authors` tidak lagi tersimpan di HTML statis (syarat dari review Fase 2).
- Halaman publik tetap ○ static.

**Tambahan dari review (2026-11-10), wajib saat implementasi:**

- **Tinggi, sesi bisa dicabut:**
  - Tanda tangan cookie ikut memuat sidik `password_hash` (HMAC dari hash, bukan hash-nya), dan sidik itu dicocokkan saat cek database.
  - Dengan begitu, reset password oleh admin langsung membatalkan semua sesi lama akun itu. Tanpa ini, cookie yang dicuri tetap berlaku sampai 7 hari. Tetap tanpa tabel baru.
- **Sedang, tanpa cache:**
  - `getCurrentUser()` membaca user lewat query khusus tanpa cache di `lib/data/`. Fungsi yang ber-`"use cache"` / `cacheLife("max")` tidak boleh dipakai di sini.
  - Role dan status aktif selalu dibaca dari database, bukan dari cookie.
  - Setiap Server Action di Fase 4 memanggil `getCurrentUser()` sendiri.
- **Sedang, role per halaman:**
  - Role tidak cukup dicek di layout, karena layout tidak dirender ulang saat berpindah halaman di dalam dashboard.
  - Setiap halaman admin memanggil `requireAdmin()`, dan setiap halaman dashboard memanggil `requireUser()`.
  - Sesi dibaca di dalam `<Suspense>`, atau halaman memakai `instant = false`, sesuai docs.
- **Sedang, waktu respons login:**
  - Kalau email tidak ada atau akun nonaktif, tetap jalankan scrypt terhadap hash dummy dengan parameter yang sama.
  - Pesan errornya sama untuk semua kasus gagal.
- **Sedang, password dev tidak boleh ke produksi:** `db:seed -- --remote` tidak memakai `DEV_PASSWORD`. Akun contoh di sana tetap `!no-login`, dan akun sungguhan dibuat dengan `db:set-password`.
- **Sedang, gagal tertutup:** kalau `SESSION_SECRET` kosong atau kurang dari 32 byte, app berhenti dengan error, tanpa nilai cadangan.
- **Sedang, logout:** lewat Server Action (POST), bukan link atau route GET, supaya tidak terpicu oleh prefetch atau oleh situs lain.
- **Rendah:**
  - **`?next=`:** kalau ditambahkan, hanya terima path yang diawali `/` dan bukan `//` atau `/\`.
  - **Parameter scrypt:** dibatasi ke nilai yang diizinkan, dengan `maxmem`.
  - **Reverse proxy:** di belakangnya perlu `serverActions.allowedOrigins`.
  - **Session fixation:** tidak menjadi masalah, karena cookie selalu dibuat baru saat login.

**E2E:**

- Login sekali dengan `DEV_PASSWORD`, lalu sesinya dipakai ulang untuk semua test dashboard.
- Test baru:
  - tanpa login, dashboard dialihkan ke login;
  - author tidak bisa membuka halaman admin;
  - password salah ditolak;
  - akun nonaktif ditolak.

## Hari 1 (Sel 10 Nov): perbaikan fokus palet ⌘K

**Tindak lanjut lama:** dari persiapan Fase 2, ditulis berdasarkan membaca kode. Isinya: menekan Ctrl+K lagi saat palet terbuka menimpa elemen tujuan fokus, sehingga fokus jatuh ke `body` saat palet ditutup.

**Hasil:**

- **Bug ini tidak terlihat di Edge.** Test E2E baru lolos tanpa perbaikan, baik saat palet ditutup dengan Esc maupun dengan klik di luar palet. Palet memakai `<dialog>` bawaan dengan `showModal()`, yang saat ditutup sudah mengembalikan fokus ke elemen sebelumnya. Semua jalur tutup lewat `dialog.close()`.
- **Perbaikan tetap dipasang sebagai cadangan:** tujuan fokus hanya disimpan saat palet belum terbuka (ref `isOpen`). Logika ini benar untuk browser yang tidak mengembalikan fokus sendiri.
- **Test disimpan sebagai pengaman:** "a second Ctrl+K while quick search is open keeps where focus returns". Komentarnya menyebut terus terang bahwa test ini lolos dengan atau tanpa ref `isOpen`.
- **`code-reviewer`:**
  - Perbaikannya benar: aman di StrictMode, saat Ctrl+K ditekan di dalam input, dan saat palet ditutup lewat navigasi.
  - Satu temuan Sedang di test (bisa flaky: klik backdrop sebelum palet tampil) sudah diperbaiki dengan menunggu palet tampil dulu.
  - Temuan untuk plan ini (1 Tinggi, 6 Sedang, 4 Rendah) dimasukkan ke "Tambahan dari review" di atas.

## Hari 2 (Rab 11 Nov): password

**Yang dibuat:**

- **`lib/auth/password.ts`:**
  - scrypt N=32768, r=8, p=1, garam 16 byte, kunci 64 byte, format `scrypt$32768$8$1$<garam>$<hash>`.
  - `verifyPassword` hanya menerima format dan parameter itu persis: parameter dibandingkan sebagai teks, dan base64url harus dalam bentuk kanoniknya.
  - Kalau tidak cocok, scrypt tetap dijalankan sekali dengan garam dummy, supaya waktunya sama. Login Jumat cukup memanggil `verifyPassword(password, "")` untuk email yang tidak ada dan akun nonaktif.
  - Password berisi surrogate tunggal ditolak.
- **`npm run db:seed`:**
  - Di komputer ini, `DEV_PASSWORD` dibuat acak di `.env.local` pada run pertama (lewat `scripts/env-file.mjs`, tidak dicetak), lalu dipakai untuk semua akun contoh, masing-masing dengan garam sendiri.
  - Dengan `--remote`, termasuk lewat tunnel `localhost`, akun contoh tetap `!no-login`.
- **`npm run db:set-password <email>`:**
  - Password diketik dua kali dan tersembunyi; minimal 8 karakter.
  - Email dicocokkan tanpa membedakan huruf besar/kecil, dan perintah ditolak kalau lebih dari satu akun cocok.
  - Tidak pernah mencetak password atau hash.

**Hasil verifikasi:**

| Cek | Hasil |
|-----|-------|
| Unit test password (format, parameter, base64 non-kanonik, surrogate, Unicode NFKC) | ✅ 5 test; semua 120 unit test lolos |

**`code-reviewer`:** tidak ada Kritis atau Tinggi. Tiga temuan Sedang diperbaiki:

- `--remote` lewat tunnel `localhost` masih memakai `DEV_PASSWORD`;
- email kembar beda huruf bisa membuat dua akun berganti password sekaligus;
- format hash yang tidak valid dijawab lebih cepat, sehingga waktu respons membocorkan email mana yang terdaftar.

Temuan Rendah yang diperbaiki: base64 non-kanonik, surrogate tunggal, dan tombol kontrol di prompt (backspace pada emoji kini menghapus satu karakter utuh).

**Syarat untuk login (Jumat):**

- Password dari form harus dicek `typeof === "string"` dan dibatasi panjangnya (misalnya 1024), karena `formData.get` bisa mengembalikan `null` atau `File`.
- Email dicocokkan dengan `lower(email)` yang sama dan ditolak kalau ambigu. Pertimbangkan migrasi unique index pada `lower(email)` di Fase 4 (kelola penulis).
- `DEV_PASSWORD` dari environment shell tidak ditimpa oleh `.env.local`. E2E harus membacanya dari sumber yang sama dengan seed.
