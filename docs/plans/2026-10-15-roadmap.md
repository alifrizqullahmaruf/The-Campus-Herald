# Roadmap: Bangun The Campus Herald, mulai dari desain

**Tanggal:** 2026-10-15
**Status:** Fase 1 ✅ selesai (2026-10-16). Fase 2–5 menunggu brainstorming.

## Context

Spesifikasi (`docs/the-campus-herald.md`) dan design system (`docs/design.md`) sudah ada, tapi kodenya masih satu halaman judul. User ingin **desain dikerjakan dulu**: semua halaman publik dan dashboard tampil sesuai design.md memakai **data contoh (mock)**. Database, login sungguhan, dan alur review baru dikerjakan di fase berikutnya, **setelah brainstorming terpisah**.

Waktu: longgar (2–4 minggu). Hosting: Vercel. Bahasa UI: **Inggris**. Login nanti: buat sendiri (bcrypt + jose, sesuai panduan Next.js).

Hasil Fase 1: website yang bisa diklik dari ujung ke ujung (beranda → kategori → artikel → pencarian → dashboard author/admin) dengan tampilan final. Data tinggal diganti dari mock ke database tanpa mengubah komponen.

## Keputusan arsitektur Fase 1 (supaya Fase 2 tidak membongkar ulang)

1. **Lapisan data terpisah.** Semua halaman mengambil data lewat fungsi di `lib/data/` (mis. `getPublishedArticles`, `getArticleBySlug`, `getMostRead`, `searchArticles`, `getArticlesByAuthor`). Sekarang isinya membaca mock; di Fase 2 isinya diganti query database. Komponen tidak tahu sumber datanya.
2. **Tipe mengikuti skema spesifikasi.** `lib/types.ts`: `User`, `Article`, `Category`, `ArticleStatus`, `Role`, sesuai tabel `users`, `articles`, `categories` di spesifikasi tahap 06.
3. **Satu sumber pemetaan kategori.** `lib/categories.ts`: slug, nama, deskripsi, token warna, warna teks (putih untuk Academics), ikon. Dipakai oleh kartu, pill, badge, dan pencarian.
4. **Route groups.** `app/(public)/…` dengan header dan footer, `app/(dashboard)/…` dengan sidebar. Layout masing-masing terpisah.
5. **Server Components secara default.** Client component hanya untuk bagian interaktif: menu HP, palet ⌘K, filter pencarian, editor, form. Dengan `cacheComponents` aktif, halaman yang membaca `searchParams`/`params` dibungkus `<Suspense>`.
6. **Dashboard di Fase 1 = pratinjau.** Belum ada login, jadi halaman dashboard memakai user mock (author/admin). Tombol hanya mengubah state di layar, tidak menyimpan. Diberi banner "Preview – not connected".

## Fase berikutnya (dibrainstorm dulu sebelum dikerjakan)

| Fase | Topik | Yang akan dibahas |
|------|-------|-------------------|
| 2 | Database | Penyedia PostgreSQL di Vercel (Neon / Supabase / lainnya), ORM (mis. Drizzle), migrasi dari skema tahap 06, seed 5 kategori dan admin pertama, penyimpanan gambar. Isi `lib/data/*` diganti query sungguhan. |
| 3 | Login | bcrypt + sesi jose di cookie, Data Access Layer (`getCurrentUser`), `proxy.ts` untuk redirect cepat, pengecekan role di setiap Server Action |
| 4 | Alur kerja | Server Actions: simpan draft, submit, approve/reject, kelola author; upload gambar; `view_count`; pencarian full-text PostgreSQL; revalidasi cache dengan `cacheTag` |
| 5 | Rilis | Test E2E alur lengkap, keamanan (sanitasi HTML editor, rate limit login), isi tahap 08–09 spesifikasi, demo final |
