# Plan: Upgrade Next.js 16.4.0 → 16.4.3 (keamanan)

**Tanggal:** 2026-10-27
**Status:** Selesai, terverifikasi, di-commit ke `main` dan di-push

## Tujuan

`next` 16.4.0 terkena advisori keamanan yang sudah dipublikasikan. Naikkan `next` (dan `eslint-config-next`, yang versinya selalu disamakan) ke **16.4.3**, versi `latest` di npm. Sekalian set `experimental.agentUpgrade: "security"` di `next.config.ts` agar pengingat upgrade memakai kebijakan keamanan (nilai ini sama dengan default 16.4.x; sekarang ditulis eksplisit). Konfigurasi lain tidak diubah.

Plan ini menggantikan draft `2026-10-23-next-16-4-2.md` (tidak pernah dijalankan, hanya ada di checkout utama).

## Pemeriksaan duplikat

- Branch lokal/remote dan commit: tidak ada pekerjaan yang sama selain worktree lama `.claude/worktrees/next-16-4-3` (belum di-commit, isinya sama dengan target). User memilih melanjutkan worktree itu.
- PR terbuka: `gh` tidak terpasang; dicek lewat GitHub API publik, tidak ada PR terbuka.

## File yang berubah

- `package.json`: `next` dan `eslint-config-next` 16.4.0 → 16.4.3 (tetap dikunci persis).
- `package-lock.json`: hanya `next`, `@next/env`, `@next/swc-*`, `eslint-config-next`, `@next/eslint-plugin-next` (semua 16.4.3) dan rentang opsional `sharp` `^0.35.5` di metadata `next` (`sharp@0.35.5` sudah terpasang sejak sebelumnya).
- `next.config.ts`: `experimental.agentUpgrade: "security"`.

## Perubahan dari plan

- Tidak ada perubahan kode aplikasi yang diperlukan.
- Build pertama gagal (`Cannot read properties of null (reading 'useContext')` saat prerender). Penyebabnya lingkungan, bukan upgrade: shell sesi ini mewarisi `NODE_ENV=development` (plus `NEXT_RUNTIME`, `TURBOPACK`, `NEXT_PRIVATE_START_TIME`) dari proses `next` yang memulainya, dan Next memperingatkan "non-standard NODE_ENV". Dengan variabel itu dihapus, build lolos. Build dan E2E di bawah dijalankan dengan lingkungan bersih.
